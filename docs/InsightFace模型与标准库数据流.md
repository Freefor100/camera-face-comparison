# InsightFace 模型与标准库数据流

本文只解释当前项目实际加载、实际调用和实际保存的内容。模型文件的输入输出形状由本地
`data/models/buffalo_l/*.onnx` 直接读取；运行流程对应当前源码，不把可选模型写成已经使用。

## 1. InsightFace、buffalo_l 与 ArcFace 分别是什么

- **InsightFace** 是人脸分析开源项目及 Python 工具包。它负责组织模型加载、图像预处理、
  人脸检测、关键点对齐和身份特征提取，不是本项目完整的业务系统。
- **buffalo_l** 是 InsightFace 发布的一组预训练 ONNX 模型，不是一个单独网络。官方模型表将
  它描述为 `SCRFD-10GF + ResNet50@WebFace600K + 2d106/3d68 + Gender&Age`。
- **ArcFace** 首先是一种训练人脸特征网络的加性角度间隔损失。当前程序不执行 ArcFace 训练；
  它使用已经训练好的 `w600k_r50.onnx` 输出身份特征向量，再由本项目完成多样本聚合、1:N
  检索、Unknown 阈值判定、日志、数据管理和界面展示。

依据：[InsightFace 官方 Model Zoo](https://github.com/deepinsight/insightface/blob/master/model_zoo/README.md)、
[SCRFD 论文](https://arxiv.org/abs/2105.04714)、
[ArcFace 论文](https://openaccess.thecvf.com/content_CVPR_2019/html/Deng_ArcFace_Additive_Angular_Margin_Loss_for_Deep_Face_Recognition_CVPR_2019_paper.html)。

## 2. buffalo_l 内五个模型文件

| 文件 | 原始 ONNX 输入 | 原始 ONNX 输出 | 功能 | 当前程序是否逐图运行 |
| --- | --- | --- | --- | --- |
| `det_10g.onnx` | `input.1: [1,3,H,W]`，程序检测尺寸为 640×640 | 三个尺度的置信度、框回归和五点关键点，共 9 个张量 | SCRFD-10GF 人脸检测 | 是 |
| `w600k_r50.onnx` | `input.1: [N,3,112,112]` | `683: [1,512]` | 从对齐人脸提取 512 维身份特征 | 是，只对最终选中帧运行 |
| `2d106det.onnx` | `data: [N,3,192,192]` | `fc1: [1,212]` | 106 个二维关键点 | 否 |
| `1k3d68.onnx` | `data: [N,3,192,192]` | `fc1: [1,3309]` | 3D 人脸参数，经适配器恢复 68 个三维关键点和姿态 | 否 |
| `genderage.onnx` | `data: [N,3,96,96]` | `fc1: [1,3]` | 两个性别分数和一个年龄回归值 | 否 |

`FaceAnalysis` 启动时会扫描模型目录以识别文件类型，但本项目用
`allowed_modules=["detection", "recognition"]` 只保留检测与身份特征模块；其余三个模型不参与
每张图片的推理。额外关键点与性别年龄都不能直接回答“这是谁”。

### 2.1 检测模型输出如何变成程序字段

对 640×640 输入，`det_10g.onnx` 的三个检测尺度分别产生 12,800、3,200 和 800 个位置：

- 每个位置 1 个检测分数；
- 每个位置 4 个框回归值；
- 每个位置 10 个关键点坐标值，即左右眼、鼻尖、左右嘴角共 5 点。

InsightFace 完成解码、阈值过滤和非极大值抑制后，本项目取得：

```text
bbox             = (左, 上, 右, 下)
detection_score  = 检测置信度
landmarks        = 5×2 关键点坐标
blur_variance    = 人脸框区域的拉普拉斯方差
```

`blur_variance` 不是模型输出，而是本项目用 OpenCV 计算的清晰度指标；它只用于五帧排序和界面
提示，不能证明画面一定真实清晰，也可能被锐化噪声抬高。

### 2.2 身份特征模型的输入输出

识别前，InsightFace 用检测模型给出的五点关键点做相似变换，把人脸对齐并裁剪为 112×112。
`w600k_r50.onnx` 的 ResNet-50 主干接收该对齐人脸并输出 512 个浮点数。程序再进行 L2 归一化：

```text
embedding = raw_embedding / ||raw_embedding||₂
```

这 512 个数是网络学习到的身份表征，不分别对应“眼睛大小”“鼻子长度”等可人工命名属性。
同一身份的向量方向通常更接近；两个单位向量点积就是余弦相似度。原始人脸图片仍然只用于检测、
对齐、质量测量和特征提取，标准库检索不直接逐像素比较图片。

## 3. 当前点击摄像头识别的完整流程

```text
点击“抓拍并识别”
  ├─ 立即复制第 1 帧并启动一个识别工作线程
  ├─ 主线程每隔 80 ms 继续复制一帧，共 5 帧
  └─ 工作线程在帧到达时依次运行人脸检测
          ↓
     跳过无人脸或多人脸帧
          ↓
     按人脸区域拉普拉斯方差从高到低排序
          ↓
     只对最清晰候选运行五点对齐和 512 维身份特征提取
     （特征提取失败时尝试下一候选）
          ↓
     与内存中的 P×512 人员平均特征矩阵做一次矩阵乘法
          ↓
     最高分达到固定阈值 0.5557855367660522 → 输出该身份
     否则 → Unknown
          ↓
     写一条识别日志并更新界面
```

因此当前实现不是“5 帧分别与整个标准库识别，再选最高身份分数”。它是“5 次检测与清晰度测量，
1 次身份特征提取，1 次标准库检索”。采集等待与前几帧检测在同一时间窗口内重叠，但模型调用仍
由一个工作线程串行执行，避免五个线程同时争用同一 CUDA 会话。

## 4. 添加本地图片时保存了什么

### 4.1 图片流程

1. `ImageInput.from_file()` 用 OpenCV 解码用户选择的文件，并复制成连续 BGR 数组。
2. 录入服务要求每张输入恰好有一张可提取身份特征的人脸。
3. 程序把 BGR 数组重新编码为 JPEG，因此不是原文件逐字节复制；原文件名、绝对路径和 EXIF
   不进入数据库。
4. 新建身份先写入临时目录：
   `data/faces/.staging/<person_id>/sample_001.jpg`。
5. 全部图片处理成功后，目录原子移动为：
   `data/faces/<person_id>/sample_001.jpg`。
6. 追加样本使用：
   `data/faces/<person_id>/sample_<operation_id>_<序号>.jpg`。

任意输入失败会清理本次临时文件，不创建只有一部分样本的新身份。人员只需一张有效样本即可
参加识别；追加多张样本是改善身份表示的可选操作。

### 4.2 SQLite 保存内容

`data/face_library.sqlite` 中：

- `persons` 保存人员 UUID、显示名称和创建时间；
- `face_samples` 保存人员 UUID、相对图片路径、`float32` 特征向量 BLOB、向量维数、五项原始
  质量指标、来源类型、图片 SHA-256、特征向量 SHA-256 和创建时间；
- `recognition_logs` 保存每次识别的第一/第二候选分数、判定规则、耗时和失败原因。

数据库不保存原图二进制，也不保存原图片绝对路径。图片哈希检查的是程序保存到 `data/faces/`
中的 JPEG；向量哈希检查的是 SQLite 中 `embedding_blob` 的字节。启动、成功录入后和手动复查时，
程序验证 SQLite、外键、图片文件及两个哈希。它能发现意外缺失或替换，但不是对抗能同时修改文件、
数据库和哈希的攻击者的密码学防篡改方案。

### 4.3 多样本如何用于识别

应用启动或标准库更新后，对每个人执行：

```text
逐张样本向量 L2 归一化
  → 求算术平均
  → 再做一次 L2 归一化
  → 得到该人员的一条 512 维平均特征向量
```

所有人员按 `person_id` 排序后组成只读连续 `float32` 的 `P×512` 内存矩阵。每次识别只计算
`scores = prototype_matrix @ query_embedding`，不重新读取全部 SQLite 样本。人员平均特征向量
不写入数据库；原始样本是唯一持久化事实，启动时可以重新构建平均特征。

## 5. 本项目在 InsightFace 之外完成的工作

预训练模型只提供检测结果和单张人脸的身份特征。本项目自行完成了：

- 摄像头与本地图片两类输入；
- 多样本人员标准库、事务写入、图片管理、哈希检查和动态刷新；
- Mean Prototype 人员表示与 CPU 内存矩阵 1:N 检索；
- 使用公开数据集选择聚合方法和 Unknown 阈值；
- 五帧质量择优、检测/特征拆分和采集—检测流水线；
- Known、Unknown、Invalid 三类结果、日志、桌面界面和离线运行。

这些系统级设计决定了预训练模型如何被使用、何时拒识、如何扩容、怎样保证结果可复现，也是本
课程设计的主要实现工作。
