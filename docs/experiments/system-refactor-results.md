# 系统可靠性重构与短性能复测

## 1. 本轮要解决什么

本轮于 2026-10-13 在 `main` 上实施，审查起点为 `e9f2204`。目标不是重新设计识别算法，
而是修正事务提交、文件补偿、数据库诊断、任务结束和界面提示之间的边界。此前已经完成的
数据集标定和本人摄像头验收继续保留，不用这次小规模回放代替识别率实验。

以下内容保持不变：人员平均特征向量、最高分阈值 `0.5557855367660522`、CPU 精确矩阵
检索、五帧 80 毫秒采样，以及采集和检测重叠。没有更改表结构，没有增加旧数据兼容或迁移。
真实演示数据库、原始照片、模型和已有缓存没有被本轮故障复现改写；`report/` 未修改或提交。

## 2. 发现的问题如何修正

| 原问题 | 当前处理 | 对应证据 |
| --- | --- | --- |
| 提交失败后事务仍可能保持活动，图片补偿先删除文件 | 提交纳入回滚范围；回滚失败隔离连接并保留文件，暂停业务要求复查 | SQLite authorizer 在临时库拒绝提交、回滚；验证连接状态、后续事务与文件保留 |
| 业务冲突后回滚失败被误分类为普通输入问题 | 原异常保留，同时传递事务结果不明标记，控制器撤销库健康状态 | 真实追加重复图片后拒绝回滚，窗口识别按钮禁用并显示复查要求 |
| 一条坏样本阻断整库检查，删除后解码才报错 | 元信息与向量解码分离，删除前准备返回数据；坏记录逐项诊断 | 错误维度、质量整数转换溢出和其他坏记录同时注入；删除不解码坏向量 |
| 哈希一致但向量或归属不合法 | 强制 512 维有限非零向量，验证每人样本与平均向量；受管路径独占 | 错误维度、NaN、全零、无样本人员、共享路径等临时库场景 |
| 人员、样本和矩阵来自不同读取时刻 | 一次读事务取得原始记录，检查、展示目录与矩阵复用这份记录 | 仓库一致读取契约、矩阵等价测试；运行时不再逐人二次读取 |
| 坏库导致启动失败，失败处理再次读取同一坏记录 | 窗口先创建，后台打开和检查；新连接复查，成功后发布快照 | 临时损坏库仍能构造窗口，外部恢复后复查恢复识别 |
| 日志故障覆盖已完成的判定 | 判定仍显示，单独提示未保存；不可用时暂停后续业务 | 在日志边界注入数据库错误，未知判定不被替换成系统失败 |
| 提前失败仍采集，迟到通知覆盖界面，线程未退即关窗 | 统一任务编号与状态；失败立即停采集、退出才释放；异步等待所有后台资源 | 真正 Qt 工作线程、输入队列与受控阻塞替身；并非真实驱动永久故障 |
| 库删除消息进入识别卡片，旧结果残留 | 消息分属识别区、标准库页和设备区；新识别、已提交修改、复查发布快照均重置结果 | 删除后识别卡片为空；另一连接改名后复查，旧姓名和照片不再保留 |
| 已诊断的坏路径在展示时再次抛异常 | 单张坏路径显示占位，继续构造其余样本卡片 | 含 NUL 字符路径与正常元信息并存的离屏页面场景 |
| 环境路径指向基础解释器，后端说明忽略混合会话 | 使用当前环境安装路径，分别读取检测和特征模型会话 | 安装路径测试、混合会话显示测试、真实 CUDA 与 CPU 回放 |
| 加载未使用会话，主线程读取大图，全库姓名重复构建 | 只打开两个模型；后台有界缩略图；快照预建只读姓名映射 | 两文件加载契约、真实同后端回放、缩略图测量与视觉检查 |

最后一轮独立审查确认的四项遗漏均先新增失败复现，再修正：事务不确定状态、复查旧结果、
质量转换溢出、非法路径展示。对应改动为 `7d8c096`，不是从“测试通过”倒推没有问题。

## 3. 数据和计时口径

短回放直接调用正式识别服务、当前模型和冻结参数。自然 LFW 的同一协议与已有原始特征缓存
用于准备标准库，规模为 3、100、4588 个有效身份。固定选择五组同身份五张图片序列，三个规模
复用同一批输入；单帧取各组第一张，五帧按 80 毫秒间隔提交。每种路径先预热两次，再记录五次。
每份报告共 30 条记录，五帧序列共涉及 25 张不同图片；这是可靠性和耗时回放，不是准确率估计。

小库仅取固定大库的前若干身份，有些输入身份自然不在小库中。每种规模的单帧有一条多人脸无效
输入；4588 人时其余四条单帧和五条多帧均被正确接受。不能把小库中的未知结果当作误拒。

回放总用时从服务请求开始，到判定和日志处理结束；图片解码另外记录，二者之和是文件输入的
回放总时间。摄像头采集窗口固定约 320 毫秒，检测在窗口内重叠，因此各阶段累计时间不能直接
相加。该回放不包含真实驱动抖动、Qt 通知往返和页面生成，也不能冒充人工点击到显示的精确
测量。当前界面的“识别用时”仍包括这些可观测的界面任务阶段，显示器最终呈现不单独计时。

重构前指本轮模型加载与姓名映射清理前的路径，当时已经具有内存矩阵和流式五帧检测；不是
阶段 5C 的逐次整库检查基线。CUDA 原始报告分别在 18:22 与 18:56 采集，优化代码随后封存为
`a831710`。CPU 参考通过仅实验使用的旧加载顺序运行。汇总命令、原始文件 SHA-256 和协议
SHA-256 保存在比较 JSON 中，原始报告不被汇总覆盖。

原始产物均位于 Git 忽略的 `data/experiments/refactor/`：

- `baseline.json`、`optimized.json`：CUDA 重构前后原始阶段记录；
- `cpu-reference.json`、`cpu-validation.json`：相同 CPU 后端的加载参考与当前路径；
- `library-loading.json`：最初单次库读取测量，仍保留；
- `library-loading-repeated.json`：三个规模各三次的加载原始记录与统计；
- `thumbnail-decoding.json`：同一公开肖像各五次解码记录；
- `comparison.json`：所有阶段的平均值、中位数、95% 分位及等价核对；
- `ui/idle.png`、`ui/matched.png`、`ui/library.png`：本轮临时库的离屏页面截图。

中位数表示一半测量快于该值、一半慢于该值；95% 分位表示约 95% 测量不超过该值。每组只有
五次或三次，尾部统计仅用于保留原始波动，不能据此给出大规模性能保证。

## 4. 识别结果与短耗时对照

### 4.1 等价性

CUDA 前后 30 条、CPU 前后 30 条的第一和第二候选、选中帧、有效帧数和判定全部一致，同后端
分数最大绝对误差为 0，满足 `1e-6` 要求。CPU 与 CUDA 的采样判定和选帧也相同，但分数最大差
为 `0.000724837`；这是跨后端数值差异，不是重构误差。不能声称两种硬件在阈值附近永远同判。

### 4.2 CUDA 服务请求总用时

表中每格为“中位数 / 95% 分位”，单位毫秒。

| 身份数 | 单帧重构前 | 单帧重构后 | 五帧重构前 | 五帧重构后 |
| --- | --- | --- | --- | --- |
| 3 | 25.207 / 25.503 | 25.407 / 25.537 | 344.710 / 350.325 | 342.534 / 346.555 |
| 100 | 24.592 / 30.000 | 25.684 / 26.950 | 343.711 / 346.470 | 342.279 / 346.147 |
| 4588 | 23.225 / 27.172 | 26.210 / 27.890 | 344.292 / 347.081 | 344.535 / 347.367 |

本轮没有证明服务总用时稳定下降，单帧中位数反而略有上升，因此不宣称端到端加速。前述
阶段 5C/5D 的历史收益仍有效，但不能拿来代替本轮结果。此次主要收益是消除错误处理与界面
资源释放问题，并减少启动、复查的重复读取。

结果组装未单独插桩，Qt 往返和页面更新也没有前后量化，本轮不把它们写成已测加速。

### 4.3 模型启动

CUDA 模型加载单次观测为 1559.560 → 1376.361 毫秒；CPU 加载参考为 3548.991 → 1039.914
毫秒。直接打开两个所需文件并避免重复设置相同 CPU provider，减少了无用会话初始化。
这些是每个进程一次的观测，不是模型加载时间的稳定统计，也不属于单次识别用时。

## 5. 标准库读取与缩略图

### 5.1 临时标准库加载

复制同一协议中的真实 LFW 参考图到临时目录，用已有有效特征构造三种库，分别有 3、173、7465
张有效样本。每种重复三次。库检查、同源矩阵构建和逐人查询参考分开计时；参考仍使用当前
严格向量解码器，比较的是查询策略，不是直接测量旧应用完整启动。

| 身份 / 样本数 | 完整检查中位数 | 逐人查询构建中位数 | 同源记录构建中位数 |
| --- | --- | --- | --- |
| 3 / 3 | 0.448 ms | 0.126 ms | 0.071 ms |
| 100 / 173 | 16.028 ms | 5.028 ms | 1.598 ms |
| 4588 / 7465 | 705.864 ms | 19770.291 ms | 68.125 ms |

三个规模的矩阵最大元素误差均为 0。大库参考为每人分别执行样本查询，未索引的所属人员查询
重复扫描样本表；当前路径读取一次后按身份聚合，避免这一重复。完整检查仍需读取图片哈希，
并未凭空消失；它在后台执行，且查询期间不再执行。当前库修改后选择从已检查记录重建整个矩阵，
没有声称只更新一行，也没有另外持久化平均向量或新增数据库索引。

### 5.2 缩略图

同一公开肖像为 2400×3000 PNG；当前页面保存的缩略图是 204×256，保持比例。原分辨率解码
五次中位数为 97.430 毫秒，缩略解码中位数为 98.682 毫秒，未证明解码加速。PNG 插件仍可能
先解码大图再缩放；“缩到 256 像素”不等于所有格式都减少解码计算。

可以确认的改善是页面与缓存不再持有全尺寸图像；按 4 字节每像素估算，单张像素缓存约从
28.8 MB 减少至 0.209 MB，不含对象与解码临时内存。解码移入最多两个后台任务，缓存最多
64 张，选择变化时旧加载结果不再回填。源文件没有改写或覆盖。

## 6. 验收与复现

自动化验证使用临时 SQLite、真实 Qt 事件循环及工作线程，只替换外部模型或设备边界，不接触
真实图库。覆盖提交和回滚失败、文件补偿、坏向量与质量记录、共享路径、坏库恢复、日志警告、
采集失败、迟到通知、异步关闭、结果清空、缩略图与混合后端。提交前全量测试为 102 项通过，
Ruff、源码编译和差异检查均通过；单元测试数量不作为识别能力结论。

真实模型回放使用本地 LFW，分别执行 CUDA 和 CPU。离屏界面另用公开 Obama 肖像与临时库，
完成一次本地识别并检查未启动、识别成功、标准库详情三种状态；这种同肖像链路只证明事件与
显示贯通，不证明独立识别准确率。截图已人工查看，双栏、判定字段和单样本卡片保持原设计。
此前由操作者完成的本人已登记识别、未知拒识与设备后端确认不要求重新做。

## 7. 提交与剩余边界

已形成独立实现提交：`ed95894`（提交与补偿）、`ea1f7c8`（一致读取与诊断）、`919cf34`（任务
协调和提示归属）、`a831710`（模型与缩略图）、`7d8c096`（最终审查四项边界修正）、`9f2f47d`
（可复用短性能记录入口）、`70a1d47`（删除只读元信息及补偿、锁竞争、一致读取复验）。
文档与最终验证单独封存。

已接受而不伪装成已解决的边界如下：

- 图片与数据库不是跨资源断电事务；事务不明、清理失败或外部修改可能留下文件，需要人工查看警告。
- 整体不可读的库不开放修复性删除，不自动重建或修复；应先在程序外恢复数据，再点击复查。
- 数据库读快照不意味着文件系统也具有同一时间点快照；外部修改不实时监控，SHA-256 不是身份认证。
- 协作式关闭不会强制杀死卡住的驱动或 GPU；资源未退出时窗口继续等待，不保证最长退出时间。
- 缩略图缓存数量有界，但极多样本的卡片创建、排队和元信息处理仍在界面侧，不声称无限规模无阻塞。
- 本轮没有量化 Qt 往返或页面生成的前后收益，没有将这次服务回放升级为完整人工点击耗时证明。
- Windows、macOS 保留跨平台代码和安装说明，但不声称已在本机完成真实硬件测试。

不新增活体检测、实时关键点叠加或大型索引，也不重新开启阈值搜索。

## 8. 后续复查发现的问题与局部修复

上一轮完成不等于所有业务分支都没有缺陷。后续复查又发现正常重名会禁用有效库、两种特殊坏
记录会造成“修改已提交却返回失败”、姓名对话框期间摄像头停止会产生空帧异常，以及按钮与
窗口布局、旧提示等界面问题。本节另行保留证据，不改写前述性能报告或历史测试结果。

本轮首先保存对应的失败复现，再进行以下修正：

- 姓名冲突由明确的业务异常反馈中文说明，不进入库损坏流程；回滚不确定标记仍优先处理。
- 改名提交前解析原记录并准备返回对象；坏创建时间不再使姓名先变更后报错。
- 删除后的引用检查遇到坏字段类型时留图并报告清理警告，后续复查失败会撤销旧矩阵，保留
  已提交的删除事实。整体坏库仍由人工恢复，不新增修复性删除功能。
- 摄像头新增在打开姓名对话框前复制画面；“设备已打开”和“首帧已收到”分开记录，摄像头
  录入须有画面，追加须有人员选择。选择和设备变化都会更新按钮。
- 图片不再用像素尺寸反向撑大窗口；结果区可在长说明时局部滚动。普通结果在 1024×768 下
  同时可见来源、识别用时和画面建议，窗口放大后仍可缩回该尺寸。
- 缩略图最小布局提示固定于控件边界，而非已缩放图片的像素尺寸，缓存命中不再导致高度跳变。
- 结果重置同时清除旧错误工具提示；空库判定明确说明未进行身份比较，而不是虚构阈值比较。

自动复验只围绕这九个已复现问题，不重复数据集标定或正式识别率实验。额外用本地 CUDA 模型、
公开 Obama/Merkel 肖像和临时标准库查看实际界面；Obama 作为已登记输入得到识别成功，2011 年
Merkel 单人肖像作为未登记输入得到未知人员。2015 年 Merkel 图片出现无效输入，按原有输入
规则处理，没有改模型或阈值以迎合样例。这些小样例仅证明本次事件与显示链路，不是准确率结果。
两张公开图片不进入真实演示标准库，截图及故障库均为临时产物。
