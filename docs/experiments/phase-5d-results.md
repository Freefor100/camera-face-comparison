# 阶段 5D：检测/身份特征拆分与摄像头流水线结果

## 1. 结论

当前摄像头识别已由“收齐 5 帧后，每帧都执行检测和身份特征提取”改为：

1. 点击后立即启动识别工作线程；
2. 主线程每隔 80 毫秒提交一帧，工作线程在帧到达时执行检测；
3. 收齐 5 帧后按人脸区域清晰度排序；
4. 只对最清晰候选执行一次五点对齐和 512 维身份特征提取；
5. 只执行一次人员标准库检索与 Unknown 判定。

在本机 CUDA 环境、4,588 个 LFW 标准库身份、10 条五帧序列下：

- 点击到结果的中位耗时由 **449.756 ms 降至 362.836 ms**，减少 86.920 ms，即 19.3%；
- 95% 请求不超过的耗时由 **467.339 ms 降至 368.916 ms**，减少 21.1%；
- 每条序列都检测 5 帧；旧路径身份特征提取次数中位数为 4，新路径固定为 1；
- 10 条序列的识别状态、人员、有效帧数、选中帧、第一和第二候选分数全部一致，最大分数绝对误差
  为 0。

因此这次优化已经实际接入。它减少了重复身份特征提取，并让前四帧检测与后续帧的采集等待重叠，
没有修改模型、人员聚合方法或固定阈值。

## 2. 对照方法

数据与配置：

- 图片：自然 LFW；
- 标准库：4,588 个有效身份组成的人员平均特征矩阵；
- 输入：10 个身份，每个身份固定 5 张待识别图片；
- 采集模拟：第 1 帧在点击时可用，其余帧按 80 毫秒间隔由独立生产线程提交；
- 模型：本地 InsightFace `buffalo_l`，检测尺寸 640×640；
- 后端：`CUDAExecutionProvider`，设备编号 0；
- 预热：每条路径正式记录前运行 2 条序列；
- 识别：人员平均特征向量 + 最高候选分数阈值 `0.5557855367660522`。

旧路径先等待固定 320 毫秒收齐 5 帧，然后对每张有效单脸依次运行检测、对齐和身份特征提取，再
选择最清晰帧。新路径从第 1 帧开始就执行检测，只在全部检测结束后为最清晰帧提取身份特征。
两条路径共用同一个真实 `FaceEngine`、同一标准库、同一图片顺序和同一日志仓库。

命令：

```bash
.venv/bin/python -m experiments.commands.benchmark_production_runtime \
  --data-dir ./data \
  --lfw-root ./data/datasets/lfw_funneled \
  --protocol ./data/experiments/phase4/protocol.json \
  --cache ./data/logs/cache/lfw_raw.sqlite \
  --output-dir ./data/experiments/phase5d/split-inference-pipeline \
  --identity-count 4588 --sequence-count 10 --warmup-count 2 --frame-count 5
```

## 3. 分阶段耗时

“中位数”表示 10 次记录排序后的中间水平；“95% 分位”表示约 95% 的记录不超过该数值。所有
耗时单位都是毫秒。模型阶段为每条五帧序列的累计模型时间，不等于点击到结果耗时，因为新路径
中的部分检测与 320 毫秒采集窗口同时发生。

| 阶段 | 旧路径中位数 | 新路径中位数 | 旧路径 95% 分位 | 新路径 95% 分位 |
| --- | ---: | ---: | ---: | ---: |
| 五帧检测累计 | 85.088 | 94.794 | 91.931 | 100.883 |
| 身份特征提取累计 | 29.924 | 8.313 | 38.664 | 9.763 |
| 质量指标计算 | 0.148 | 0.172 | 0.168 | 0.222 |
| 清晰度排序 | 0.006 | 0.004 | 0.007 | 0.006 |
| 4,588 人矩阵检索 | 1.783 | 1.751 | 2.651 | 3.560 |
| 阈值判定 | 0.019 | 0.021 | 0.026 | 0.024 |
| SQLite 日志写入 | 14.338 | 14.448 | 16.141 | 15.330 |
| 点击到结果 | **449.756** | **362.836** | **467.339** | **368.916** |

检测累计时间在两组间存在约 10 毫秒波动，但检测调用次数没有改变。主要计算削减来自身份特征提取
次数减少；主要端到端收益来自采集等待与检测重叠。新路径不能低于固定 320 毫秒采集窗口，再加
最后一帧检测、一次身份特征提取、检索和日志，因此最终中位数约为 363 毫秒是合理结果。

同一次正式运行还记录了单张本地图片路径：点击到结果中位数 36.743 毫秒，其中检测 20.582
毫秒、身份特征提取 7.992 毫秒、4,588 人检索 1.685 毫秒。本地图片不使用五帧流水线。

## 4. 耗时口径与验收边界

本实验使用真实 CUDA 模型和真实 LFW 图片，但摄像头帧由线程按真实间隔回放，未测量
`/dev/video0` 或 `/dev/video1` 的驱动取帧抖动，也不包含图形界面的工作线程通知、结果区域生成和
显示器实际刷新。因此，表中的“点击到结果”是生产识别流程回放耗时，不是摄像头前人工点击后用
肉眼或录像测得的时间。它已经覆盖五帧采集等待、检测、身份特征提取、标准库检索、阈值判定和
识别日志写入，与人工操作的主要计算链路相同，所以能够反映实际体验的数量级。

桌面程序现在另外从识别任务启动时开始计时，在主线程完成结果文字和抓拍画面生成后更新“点击到
结果”栏目。该数值用于现场观察完整操作时间。显示器最终呈现画面的时间无法由界面自身准确测量，
不再作为单独验收项。数据库识别日志中的耗时用于记录识别服务内部处理时间，在日志写入前计算，
不能与完整链路数值混用。
