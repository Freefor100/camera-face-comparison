# 人脸比对系统需求分析

本文是本项目的需求分析基线，也是课程设计报告“需求与技术现状分析”部分的素材。它区分任务书要求、当前实现、后续计划和系统局限性，不把尚未完成的方案写成已经实现的功能。

## 1. 问题定义

本项目面向外置摄像头和本地图片输入，构建一个离线运行的人脸开放集 1:N 识别系统。系统需要从输入图像中检测人脸、提取特征向量，在本地标准库中搜索候选身份，并根据相似度证据输出已知人员姓名或“未知人员”。

与简单的两张图片一对一比对不同，本系统每次输入一张待识别图片，标准库中可能存在多个身份，
每个身份还可能有多张参考图片。因此系统需要同时处理：

- 摄像头帧与本地图片的统一输入；
- 无脸、多人脸、图片损坏等无效输入，以及尺寸、模糊和光照异常提示；
- 多身份标准库中的 1:N 搜索；
- 同一身份多样本的分数聚合；
- 分数不足或候选不明确时的未知人员拒识。

## 2. 使用者与使用场景

### 2.1 操作者

操作者通过桌面用户界面完成设备选择、预览、抓拍、本地图片识别、人员创建、样本追加和结果查看。课程展示时，操作者还需要能够解释系统的数据流、算法、阈值和测试结果。

### 2.2 被识别对象

被识别对象不直接操作系统，只作为摄像头前的人或本地图片中的人脸出现。其身份可能已经存在于标准库，也可能属于未知人员。

### 2.3 主要场景

1. 启动程序并加载本地模型和标准库；
2. 刷新并选择外置摄像头，查看实时预览；
3. 抓拍当前画面并进行已登记人员/未知人员判断；
4. 选择本地图片作为待识别图片进行识别；
5. 从摄像头或本地图片创建新人员；
6. 为已有人员追加不同来源、角度或质量的样本；
7. 查看人脸框、相似度、候选分差、耗时和异常原因；
8. 重启后继续使用已有标准库。

## 3. 功能需求

| 编号 | 需求 | 输入 | 输出/结果 | 当前状态 |
| --- | --- | --- | --- | --- |
| F-01 | 调用外置摄像头并支持拍照 | 摄像头设备索引、视频帧 | 实时预览、抓拍帧、设备异常提示 | 已实现并完成阶段 1 验收 |
| F-02 | 建立不少于 3 个身份的标准库 | 人员名称、至少 1 张有效图片 | 人员记录、样本图片、人脸特征向量 | 当前本地库有 7 个身份、19 张样本；现场演示仍待验收 |
| F-03 | 完成人脸开放集一对多判别 | 摄像头或本地待识别图片、标准库 | 姓名和相似度，或未知人员 | 已实现；聚合和阈值已由跨质量联合标定并接入运行时 |
| F-04 | 提供清晰、简洁、友好的用户界面 | 操作者按钮和文件选择 | 双栏预览、检测框、结果和异常反馈 | 已完成阶段 5C 界面收尾；仍需阶段 6 现场验收 |
| F-05 | 支持标准库动态扩容 | 新人员图片、已有人员追加图片 | 新增内容立即参与后续比对 | 已实现并完成阶段 1 验收 |

基础功能的验收重点是完整链路可运行，不要求所有退化图像都被强行识别。当前只有无法解码、无人脸、多人脸或无效人脸特征向量属于输入失败；其他质量指标只提示操作者调整。

## 4. 扩展功能需求

任务书将扩展功能列为基础功能之外的加分项，并列出鲁棒性优化、检测与比对时间优化等方向。本项目的开发计划同时纳入两个可分别验证的扩展，并将实现范围限定在课程时间和当前本地硬件能力可完成的内容：

- 鲁棒性扩展：短时间窗口内采集多帧，利用已有质量指标选择较可靠的帧，再进行识别；
- 时间优化：以端到端处理时间为对象，记录输入准备、检测、质量测量、特征提取、标准库检索、判定、日志和界面反馈等阶段的总耗时，定位主要耗时环节后实施小范围优化；
- 验证方式：分别比较单帧与多帧质量择优、优化前与优化后的端到端流程，固定模型、标准库、阈值、硬件和测试数据，报告成功率、拒识率、分阶段耗时、总耗时和功能代价；
- 已完成算法分析：六种人员多样本聚合和四类开放集接收规则已在固定数据上联合比较，结果已用于运行时；
- 不把极端暗光、严重模糊、强遮挡、极端侧脸、远距离小脸和支付级安全当作本课程必须解决的问题。

扩展必须保留优化前基线、问题证据、优化方案、相同条件复测结果、收益和代价。

## 5. 数据需求分析

### 5.1 输入数据

- `camera`：OpenCV 读取的 BGR 视频帧，来自外置摄像头；
- `file`：操作者选择的本地图片；
- `dataset`：只用于开发、算法比较和评测的数据集图片。

三种输入都经过同一套人脸检测、原始质量测量和特征提取逻辑。待识别图片被识别后不会自动写入标准库。

### 5.2 标准库数据

每个身份至少有一张有效参考图片。样本包含：

- 人员标识和展示名称；
- 样本图片路径和来源；
- `float32` 人脸特征向量及向量维度；
- 检测分数、脸部尺寸、清晰度、亮度和对比度原始指标；
- 图片哈希和人脸特征向量哈希；
- 创建时间及样本编号。

图片和向量是一一对应的。图片用于复核和重新处理，向量用于在线比对；程序启动时从该身份
的全部单位样本向量求平均并重新归一化，构建内存中的人员平均特征矩阵。识别时直接读取矩阵
快照，不重复读取 SQLite 样本；该派生向量仍不单独持久化，人员或样本变化后重新构建受影响
的快照。

### 5.3 配置和日志

配置保存固定聚合名称、最高分接收阈值和非阻断质量提示界限。识别日志保存时间、决策、人员、最高分、第二候选分数、候选分差、实际判定规则、耗时和异常原因，用于问题定位与实验复现。

## 6. 核心业务规则

1. 标准库录入图片必须检测到恰好一个人脸并产生有效人脸特征向量；图片损坏、无人脸、多人脸或无效人脸特征向量时拒绝；
2. 新人员只要有一张有效样本即可参与识别，不固定姿态、动作、数量或采集顺序；
3. 同一人员允许追加多张图片，图片质量可以不同；多样本不是入库门槛；
4. 每个人的全部有效样本形成归一化人员平均特征向量，待识别向量与每个人员平均特征向量计算余弦相似度；
5. 最高人员分数达到 `0.5557855367660522` 时输出第一候选姓名，否则输出未知人员；候选分差只记录和展示；
6. 图片、人脸、人脸特征向量或标准库完整性失败时输出“无效输入”，而不是把它混同为未知人员；
7. 标准库至少需要 3 个不同身份才能满足课程基础功能要求，但开发、调参和最终演示数据必须分开管理；
8. 标准库被识别时只读取本地数据，不访问网络。

## 7. 人机交互需求

- 首页能够看到当前设备、预览状态和可执行操作；
- 预览启动、停止、故障和重开状态清晰可见；
- 停止预览后不保留容易误认为实时画面的最后一帧；
- 识别结果至少显示检测框、姓名或未知人员、相似度、候选分差、耗时和原因；
- 识别结论与相似度、固定阈值、候选分差、可选帧、耗时和判定依据分区显示，避免长句堆叠；
- 标准库页面以紧凑列表显示人员和样本数量，缩略图按可用宽度自动重排并保持原图比例；
- 新增和追加操作明确区分摄像头帧、本地图片和失败原因；
- 设备打不开、图片无法解码、多人脸和标准库损坏时给出可理解的错误；质量指标异常时给出不阻断的调整建议；
- 用户界面不因模型推理、数据库写入或摄像头读取而长时间冻结。

## 8. 非功能需求

### 8.1 可运行性

当前项目选择 Python 源码运行，不制作 EXE。运行目标为支持 Python 3.11～3.13 的 Windows、Linux 和 macOS；识别使用本地 InsightFace 模型，Linux NVIDIA 环境优先 CUDA，其他环境使用 CPU 或自动回退 CPU。

### 8.2 离线与数据边界

模型准备阶段可以联网下载，正常启动和演示只使用本地模型。标准库图片、向量和日志保存在本地 `data/`，不上传外部服务。

### 8.3 可靠性

人员及样本使用原子事务写入；图片与向量分别保存哈希；程序启动、录入成功后和手动复查时
执行 SQLite、外键、图片和向量完整性检查，单次识别不重复检查。摄像头和推理错误需要转化为
用户界面可见状态，而不是导致程序崩溃。

### 8.4 可维护性与可复现性

采集、检测、质量、特征、标准库、识别和用户界面分模块组织；实验输入、协议、参数、逐样本结果和汇总指标应能够被重新运行。源码函数和关键步骤使用统一中文注释。

## 9. 技术现状与项目边界

当前采用 InsightFace `buffalo_l` 完成人脸检测和人脸特征向量提取，OpenCV 负责摄像头与
图片输入，PySide6 负责桌面图形界面，SQLite 负责业务持久化与实验分数。阶段 5B 已在
身份互斥的参数选择集上比较六种人员聚合方法、最高分阈值、仅候选分差、双条件和邻域
感知余弦（NAC），并在自然 LFW 与 XQLFW 的四个主要场景共同选出人员平均特征向量加
最高分阈值 `0.5557855`。该参数通过 3～100 人小型标准库复核后，只在独立验证集执行一次。
桌面应用现已使用相同聚合方法和参数；旧质量加权、质量分层和质量拒绝门槛已经删除。

以下问题作为系统局限性，不在当前课设范围内承诺完全解决：

- 极端暗光、严重运动模糊、强遮挡或极端侧脸造成身份信息不可见；
- 远距离小脸、低分辨率监控和跨摄像头域迁移；
- 面向所有年龄、肤色、设备和环境的统一准确率保证；
- 活体检测、照片/屏幕重放防护和支付级安全认证；
- 大规模身份库、分布式存储和高并发服务化部署。

## 11. 工程结构说明

`src/` 是源码隔离目录；`src/camera_face_comparison/` 是可导入的 Python 主包，负责应用业务模块；其下的 `ui/` 是界面子包。根目录的 `pyproject.toml` 提供安装配置和命令入口，因此根目录不需要额外放置 `main.py`。

`src/camera_face_comparison.egg-info/` 不属于源码结构，是 `pip install -e .` 自动生成的安装元数据，已被 Git 忽略，提交源码时不应包含。
