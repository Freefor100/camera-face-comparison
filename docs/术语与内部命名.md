# 术语、指标与代码名称说明

本文解释项目文档、代码和实验报告中的专业术语。正文优先使用中文名称；英文名称和代码
字段只在第一次出现时说明，后文不再用未解释的缩写代替完整含义。

## 1. 识别任务和数据角色

| 中文名称 | 英文名称或内部名称 | 本项目中的含义 |
| --- | --- | --- |
| 一对一验证 | 1:1 verification | 判断两张人脸图片是否属于同一人；XQLFW 官方图片对使用这种任务 |
| 一对多身份识别 | 1:N identification | 将一张待识别图片与标准库中的 N 个身份比较，先产生候选排序，再决定输出姓名或未知人员 |
| 开放集识别 | open-set identification | 待识别人员可能不在标准库中，因此系统必须有明确的未知人员拒绝规则 |
| 标准库 | Gallery | 已登记身份及其参考图片、人脸特征向量和人员表示的集合 |
| 参考图片 | Reference Sample | 已明确归属于某个身份、用于构造该身份人员分数的图片 |
| 待识别图片 | Probe | 本次送入系统识别的摄像头帧、本地图片或数据集图片 |
| 已登记人员图片 | Known Probe | 真实身份在标准库中，但该图片没有作为参考图片入库 |
| 未登记人员图片 | Unknown Probe | 真实身份不在标准库中，用于检查未知人员拒绝能力 |
| 参数选择集 | Calibration | 只用于比较方法、选择规则和确定阈值，不用于报告最终泛化效果 |
| 独立验证集 | Evaluation | 参数固定后只使用一次；结果不能再反过来调参 |

## 2. 人脸表示和人员分数

| 中文名称 | 英文名称或代码名称 | 定义和当前状态 |
| --- | --- | --- |
| 人脸特征向量 | embedding | InsightFace 从对齐人脸中提取的 512 维数值向量；保存和比较前做 L2 归一化 |
| 余弦相似度 | cosine similarity | 两个单位向量的点积，范围为 `[-1, 1]`，数值越大表示模型认为越相似 |
| 余弦距离 | cosine distance | 通常定义为 `1 - 余弦相似度`；当前运行时不使用距离或向量模长判定 |
| 固定单张参考图片 | Single（代码：`single`） | 每个身份固定使用路径排序后的第一张有效参考图片，不是每次随机抽取 |
| 最高样本分数 | Max（代码：`max`） | 分别比较某身份的全部参考图片，使用其中最高相似度作为该身份人员分数 |
| 人员平均特征向量 | Mean Prototype（代码：`mean_prototype`） | 同一身份全部单位人脸特征向量求平均后再次归一化；当前部署使用这种人员表示 |
| 前 K 个样本分数平均 | Top-K Mean（代码：`top_k_mean`） | 取某身份最高的 K 个样本相似度求平均；实验比较过 `K=2/3/5`，当前未部署 |
| 人员分数 | person score | 一张待识别图片与一个标准库身份之间的最终连续相似度 |
| 第一候选分数 | `top_score` | 所有身份人员分数中的最高值 |
| 第二候选分数 | `second_score` | 所有身份人员分数中的第二高值；标准库只有一个身份时为空 |
| 候选分差 | `score_gap` | 第一候选分数减去第二候选分数；当前只显示和记录，不参与判定 |
| 连续候选分数 | decision score | 尚未应用接收阈值的人员分数；保存后可以反复测试不同规则和参数，而不必重新提取人脸特征向量 |

## 3. 未知人员接收规则

| 中文名称 | 代码名称 | 判定方式和状态 |
| --- | --- | --- |
| 最高分阈值规则 | `score_threshold` | 第一候选分数不低于最低接收分数时输出该身份；当前唯一部署规则 |
| 最低接收分数 | `minimum_score` | 当前值为 `0.5557855367660522`，由跨质量参数选择集确定 |
| 仅候选分差规则 | `score_gap` | 只检查第一、第二候选分差是否达到下限；完成实验但未部署 |
| 最高分与分差双条件规则 | `score_and_gap` | 第一候选分数和候选分差必须同时达标；完成实验但未部署 |
| 邻域感知余弦规则 | NAC | 对最接近的若干身份分数做局部归一化指数计算（softmax），再检查第一候选在这些身份中的相对占比；实验收益不足，未部署 |

“评测工作点”是论文和标准中的常用说法，指在某个目标误接收率下选出的识别方法、接收
规则和参数。项目正文使用这个词时，必须同时写明目标误接收率，不能只写“工作点”。

“固定参数”表示参数选择已经结束，后续独立验证和应用复核都不得根据结果再次调整该参数。

## 4. 识别结果状态

| 中文名称 | 代码状态 | 当前行为 |
| --- | --- | --- |
| 已识别 | `matched` | 第一候选通过最低接收分数，输出对应姓名 |
| 未知人员 | `unknown` | 已完成人脸特征提取和身份比较，但第一候选分数不足 |
| 无效输入或标准库异常 | `invalid` | 图片损坏、无人脸、多人脸、无效人脸特征向量或标准库完整性失败 |
| 质量提示 | `quality_warnings` | 根据人脸尺寸、清晰度、亮度等原始指标提示用户调整；不阻断录入或识别 |

旧版本曾将检测置信度、人脸尺寸、清晰度、亮度和对比度合成质量总分，并按总分拒绝或
加权。实验表明这种总分会拒绝大量原本能正确识别的图片，因此相关运行时代码已经删除。

## 5. 识别效果指标

| 中文名称 | 缩写 | 分子和分母 |
| --- | --- | --- |
| 第一候选身份正确率 | Rank-1 | 第一候选身份正确的有效已登记人员图片数 ÷ 有效已登记人员图片总数；不检查接收阈值 |
| 有效输入正确接收率 | `TPIR_valid` | 被正确身份接收的有效已登记人员图片数 ÷ 有效已登记人员图片总数 |
| 端到端正确接收率 | `TPIR_e2e` | 被正确身份接收的图片数 ÷ 协议中全部已登记人员图片数；特征提取失败也计入分母 |
| 有效未知人员误接收率 | `FPIR_valid` | 被错误接受为任一标准库身份的有效未登记人员图片数 ÷ 有效未登记人员图片总数 |
| 未正确识别率 | FNIR | 被拒绝或识别成错误身份的已登记人员图片数 ÷ 已登记人员图片总数 |
| 特征提取失败 | FTE | 模型未能从协议图片获得有效人脸特征向量；报告必须同时给出数量和对应分母 |
| 录入失败 | FTA | 标准库参考图片无法形成有效录入样本；报告必须同时给出数量和对应分母 |

## 6. 耗时统计

一次计时实验会得到多条延迟记录，不能只报最快的一次。

| 中文名称 | 统计符号 | 含义 |
| --- | --- | --- |
| 延迟中位数 | p50 | 延迟排序后位于 50% 位置的值；一半查询比它快，一半查询比它慢 |
| 95% 分位延迟 | p95 | 95% 的查询延迟不超过该值；用于观察较慢查询的尾部情况 |
| 平均延迟 | mean | 全部计时值之和除以次数；容易受少量异常慢查询影响 |
| 端到端耗时 | E2E latency | 从输入准备到结果显示的完整耗时，不能用单独的模型推理或候选检索耗时代替 |

## 7. 候选检索实现

| 中文名称 | 对应实现 | 是否属于当前运行时 |
| --- | --- | --- |
| 每次重建人员表示 | 当前 `RecognitionService` | 每次识别都读取全部样本、重新计算人员平均特征向量，再逐人计算分数 |
| 提前计算人员表示后逐人比较 | 实验中的 Python 循环对照 | 只消除重复求平均，仍然逐个身份调用 Python 点积；不是专用向量索引 |
| CPU 全量精确矩阵检索 | NumPy `matrix @ query` | 用连续矩阵一次计算所有身份分数，再找前两名；已完成实验，尚未接入运行时 |
| CUDA 全量精确矩阵检索 | ONNX Runtime `MatMul + TopK` | 人员平均特征向量矩阵常驻显存，单个待识别向量上传 GPU；已完成实验，当前硬件上比 CPU 慢 |
| 精确扁平向量索引 | Faiss `IndexFlatIP` 等 | 仍比较全部向量，但由专用库管理向量和前 K 名检索；本项目未实现 |
| 近似向量索引 | HNSW、IVF 等 | 用图或分区减少大规模候选计算，可能漏掉真实第一名；本项目未实现 |

实验中的 `P×512` 表示含 P 行、512 列的矩阵。P 是有效标准库身份数，每一行是一名
人员的 512 维平均特征向量。“索引”只用于已经建立了明确检索结构的实现；单独执行一次
矩阵乘法时，正文应写“全量精确矩阵检索”。

## 8. 主要代码对象和实验文件

| 代码或文件名称 | 职责 |
| --- | --- |
| `FaceEngine` | 调用 InsightFace，输出检测框、关键点和归一化人脸特征向量 |
| `RecognitionService` | 连接完整性检查、输入处理、人员表示、阈值判定和日志 |
| `FaceRepository` | 保存人员、样本、原始质量指标、哈希和识别日志 |
| `RawEmbeddingCache` | 保存与接收参数无关的数据集人脸特征向量、原始指标、失败原因和耗时 |
| `decision_scores.sqlite` | 保存尚未应用拒识规则的连续候选分数，不保存接收参数 |
| `RecognitionResult` | 用户界面和数据库日志共用的一次识别结果 |
| `ExecutionBackend` | 记录人脸模型实际使用的 CUDA 或 CPU 推理后端 |

## 9. 文档使用规则

- 未知人员是正常开放集结果；无效输入是图片、人脸检测、特征提取或标准库错误，二者不能混写。
- 方法比较必须使用相同标准库、待识别图片、模型和分母，并分别报告候选排序与阈值接收结果。
- 参数选择集只负责选方法和参数；独立验证集结果不能再用于反复调参。
- 英文缩写第一次出现时写出中文含义。表格列名如果只写缩写，表格前必须先定义。
- 代码字段、文件名和命令保持原样，正文紧邻位置补充中文解释。
