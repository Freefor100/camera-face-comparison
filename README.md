# 摄像头人脸比对系统

这是一个离线运行的人脸识别桌面程序，支持摄像头抓拍和本地图片输入。程序在标准库中检索已登记人员，相似度达到阈值时显示姓名，否则显示“未知人员”。标准库支持创建人员、追加样本、修改姓名和删除数据。

系统使用 InsightFace 预训练模型完成人脸检测与特征提取。项目实现了人员多样本管理、未知人员拒识、数据集参数选择、五帧清晰度择优和处理时间优化。

- [课程设计报告](report/main.pdf)：随提交材料提供，说明设计原理、实验过程和优化结果。
- [系统设计](design.md)：介绍当前程序的数据流、模块职责和异常处理。
- [实验与复现方法](experiments/README.md)：提供数据集实验入口和结果索引。
- [文档索引](docs/README.md)：查看任务书、需求分析、模型说明与开发记录。

## 主要功能

- 摄像头实时预览、抓拍与停止；识别结果图单独显示人脸框。
- 从摄像头或本地图片登记人员，一张有效样本即可使用，同一人员可以追加多张照片。
- 在多人标准库中查找身份，显示姓名或未知人员、相似度、固定阈值和识别用时。
- 连续采集五帧，选择较清晰的有效人脸完成识别。
- 在启动、标准库修改后和手动复查时检查数据，分别处理照片、向量与数据库异常。

## 安装与启动

使用 Python 3.11～3.13。本项目已在本机 Arch Linux 上完成 CPU、CUDA 和摄像头验证；Windows、macOS 提供相应代码路径和安装命令，尚未实机验证。以下命令均在项目根目录执行，并明确使用项目虚拟环境中的 Python。

### Linux 与 macOS

先确认 Python 版本，再创建虚拟环境：

```bash
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
```

下面两种安装方式选择一种。普通 CPU 环境使用：

```bash
.venv/bin/python -m pip install -e ".[cpu]"
```

Linux x86_64 的 NVIDIA GPU 环境使用：

```bash
.venv/bin/python -m pip install -e ".[gpu]"
```

CPU 与 GPU 安装方式使用不同的 ONNX Runtime 包，不要在同一环境中同时安装两个包。更换后端时先卸载已有的 ONNX Runtime 包，再安装所选方式。GPU 版本包含 CPU 执行后端，程序无法使用 CUDA 时会尝试回退到 CPU。

首次运行前，在联网环境下载预训练模型：

```bash
.venv/bin/python scripts/prepare_models.py --data-dir ./data
```

启动程序：

```bash
.venv/bin/python -m camera_face_comparison --data-dir ./data
```

### Windows PowerShell

先安装上述版本范围内的 Python，再创建环境并安装 CPU 依赖：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[cpu]"
```

首次运行前，在联网环境下载预训练模型：

```powershell
.\.venv\Scripts\python.exe scripts/prepare_models.py --data-dir ./data
```

启动程序：

```powershell
.\.venv\Scripts\python.exe -m camera_face_comparison --data-dir ./data
```

### 离线运行与数据迁移

模型保存在 `data/models/buffalo_l/`，识别时只读取本地文件。程序实际加载 `det_10g.onnx` 和 `w600k_r50.onnx`，分别用于检测和身份特征提取。

迁移已有标准库时，先关闭程序，再复制源码以及数据目录中的 `config.toml`、`face_library.sqlite`、`faces/` 和 `models/`。目标机器按上述步骤安装依赖后启动。日常识别不需要开发数据集、实验缓存或排版检查文件；虚拟环境应在目标机器重新创建。

## 操作方法

### 人员登记与标准库管理

1. 在“标准人脸库”页选择“从本地图片新增人员”，输入姓名并选择图片；也可以在预览启动后选择“从当前画面新增人员”。
2. 图片需要能够读取、只检测到一张人脸，并成功生成身份特征。首张有效样本保存后，该人员即可参与识别，无固定姿态要求。
3. 选中人员后，通过“为选中人员导入图片”或“为选中人员添加当前画面”追加样本。
4. 可以修改姓名、删除样本或删除整个人员。单独删除样本时至少保留一条记录；需要全部删除时使用“删除人员”。

批量图片先统一校验，再写入数据库。标准库修改后更新检索矩阵，并清空上一轮识别结果。

### 摄像头与本地图片识别

1. 在“现场识别”页刷新设备、选择摄像头并启动预览。
2. 点击“抓拍并比对”，或用“选择本地图片”提交一张图片。
3. 查看本次结果图、姓名或未知人员、最高相似度、固定阈值、候选分差、识别用时和画面建议。
4. 停止预览后，左侧实时画面清空，右侧保留最近一次识别结果。

摄像头识别立即提交第一帧，之后每隔 80 毫秒提交一帧，共五帧。后台逐帧检测并计算清晰度，按清晰度从高到低尝试候选；取得有效身份特征后，只检索一次标准库。本地图片按单帧处理。

“候选分差”表示第一名相对第二名的领先程度，仅用于展示和记录。画面建议根据人脸尺寸、清晰度和光照等指标生成，只提供操作提示，不改变身份接收阈值。“识别用时”从任务启动计到结果区域更新，摄像头识别包含五帧采集等待。

## 识别方法

检测模型返回人脸框和五个关键点，程序据此对齐人脸，再提取 512 维身份特征并进行 L2 归一化。同一人员的有效样本向量先求平均，再重新归一化，得到一个人员表示。一张样本时直接使用该样本的单位向量。

程序在启动和标准库修改后构建人员特征矩阵，识别时用 CPU 矩阵乘法计算全部人员的余弦相似度。模型推理可使用 CUDA，人员检索仍在 CPU 上执行。

当前接收规则为：

```text
最高相似度 ≥ 0.5557855367660522：输出第一候选姓名
最高相似度 < 0.5557855367660522：输出“未知人员”
```

这种带未知人员拒识的一对多检索称为开放集 1:N 身份识别。规则与阈值来自 LFW、XQLFW 跨质量数据上的方案比较，确定后用于桌面程序。损坏图片、无人脸、多人脸和无效特征单独提示为输入错误。

算法原理、人员聚合公式与模型输入输出见[系统设计](design.md)和[模型数据流说明](docs/InsightFace模型与标准库数据流.md)。

### 识别记录保存在哪里

程序把识别结果追加到 `face_library.sqlite` 的 `recognition_logs` 表。每条记录使用新的唯一编号，保存写入时间、判定、人员编号、候选分数、内部处理耗时和原因。重启后继续向同一张表追加，不覆盖旧记录，也不按启动时间另建文件。记录不包含照片，当前可通过 SQLite 工具查询，界面没有历史记录页。

程序没有单独保存文本运行日志。操作错误主要显示在界面中，第三方模型和摄像头库还可能向终端输出诊断信息。数据库旁的 `face_library.sqlite-wal` 和 `face_library.sqlite-shm` 由 SQLite 管理，程序运行时不要手动删除。

`data/logs/` 主要保存实验特征缓存、第三方缓存和部分早期实验报告，不是程序识别记录目录。当前实验报告主要写入 `data/experiments/`；实验命令再次写入相同 JSON 路径时会覆盖旧报告，需要保留多次结果时应指定不同输出路径。

### 标准库异常如何处理

| 情况 | 程序处理 |
| --- | --- |
| 照片缺失、哈希变化或无法读取 | 标记照片异常并停止展示；关联向量正常时继续参与识别。 |
| 部分样本向量损坏 | 排除相应样本，使用同一人员剩余有效向量。 |
| 某人没有有效向量 | 保留人员管理信息，暂不参与检索；追加有效样本后恢复。 |
| 数据库不可读、结构或归属关系异常 | 暂停识别和修改，保留预览与复查入口；人工恢复后重新检查。 |

“重新检查标准库”会重新读取数据并更新检查状态。识别记录保存失败时，已计算出的结果仍显示，界面另外提示保存失败。事务提交、文件清理和恢复顺序见[标准库设计](design.md)。

## 实验成果与优化过程

实验分别比较了照片质量规则、人员多样本表示和未知人员接收规则。最终采用人员平均特征与最高分阈值；尺寸、清晰度、亮度和对比度用于画面建议，不作为额外的识别门槛。

实验使用自然 LFW 图片及对应的 XQLFW 质量变化图片构建一对多协议，在参数选择集上以四个主要场景的未知人员误接收率均不超过 1% 为目标。冻结规则后，评价集已登记人员的正确接收率在自然库配自然图片时为 98.26%，同一自然库配质量变化图片时为 66.30%；四个场景最高未知误接收率为 1.43%。正确接收率以全部已登记人员输入为分母，未知误接收率以成功生成特征的未知人员输入为分母。两组待识别身份不重叠；评价划分沿用早期实验，早期结果曾用于开发分析。

两项扩展是短时多帧择优和处理时间优化。多帧比较包括各位置单帧、清晰度择优、特征一致性择优和特征平均。时间优化包括停用无用推理模块、预建人员矩阵，以及在采集等待期间检测已到达的帧。

CUDA 五帧对照使用同一标准库和 10 条固定图片序列，按 80 毫秒间隔提交帧并实际执行模型。从发起到结果返回的中位耗时由 449.756 ms 降至 362.836 ms，候选与判定一致。另一次标准库开销比较复用了相同的读图与推理耗时，单独测量标准库处理部分；两类计时方法在各自记录中分别说明。

## 系统限制

- 系统面向近距离单人识别。强遮挡、极端侧脸、严重模糊和监控小脸会影响检测或身份判定。
- 五帧择优适用于短时间内仍有较好画面可选的情况。现有清晰度指标也会受锐化和噪声影响。
- 程序未实现活体检测或照片、视频重放防护。
- 完整性检查用于发现误删、替换和损坏；数据库结构性故障需要人工恢复与备份。
- 口罩识别属于[已调研但未实施的方向](docs/口罩人脸识别方案调研.md)。

## 常见问题

- **找不到程序包**：使用上述虚拟环境解释器，并先执行可编辑安装；从项目根目录启动时，未安装项目的其他 Python 解释器不会自动找到主包。
- **摄像头打不开**：检查设备是否被其他程序占用和系统权限。Linux 使用 V4L2，Windows 优先 DirectShow，macOS 优先 AVFoundation。
- **模型缺失**：检查 `--data-dir` 是否指向正确目录，以及两个实际使用的 ONNX 文件是否完整。
- **中文输入异常**：Linux KDE Wayland 会话下程序自动选择原生 Wayland 输入；显式指定其他 Qt 平台时保留该设置。
- **标准库出现警告**：在标准库页查看诊断详情；修复数据后点击“重新检查标准库”。
